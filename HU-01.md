# HU-01: Fortalecer la seguridad del token de autenticación

## Origen
- **H-AUTH-03** — `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:12-15`; `auth/src/main/java/com/bcp/workshop/auth/AuthService.java:21`.
- **H-AUTH-04** — `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:8`; `auth/src/main/resources/application.properties:4-7`.

## Contexto
- H-AUTH-03 está pendiente: el token se crea codificando campos en Base64, sin firma criptográfica; la expiración se incluye en el contenido, pero no se valida en este flujo.
- H-AUTH-04 está pendiente: hay un secreto embebido en el código y una expresión CORS amplia que permite orígenes web no restringidos.

## Ajustes necesarios
- Firmar criptográficamente los tokens y verificar su integridad y autenticidad al procesarlos.
- Validar la expiración del token y rechazar tokens vencidos.
- Retirar el secreto del código y obtenerlo mediante configuración externa, sin incluir valores secretos en el repositorio.
- Restringir CORS para que no permita orígenes mediante una expresión amplia.

## Criterios de aceptación
- Una prueba verifica que un token emitido tiene una firma criptográfica válida.
- Una prueba modifica el contenido o la firma de un token y comprueba que la verificación lo rechaza.
- Una prueba comprueba que un token vencido es rechazado.
- Una comprobación de configuración verifica que el secreto no está embebido en el código fuente.
- Una prueba CORS comprueba que se rechaza un origen que no está permitido por la configuración.

## Evidencia esperada
- Resultados de las pruebas de emisión y verificación de firma, manipulación del token, expiración y CORS.
- Evidencia de revisión del código y configuración que confirme que no contienen un secreto embebido.
